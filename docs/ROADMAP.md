### 既有取舍 / 系统限制（非待办，避免被当成 bug 反复排查）

这几条是刻意行为或平台边界，**不排期**，列在这里仅为对照：

- 图标视图的滚动位置按**行号**锚定：调整窗口宽度改变列数后「第 N 行」对应的条目整批换掉，表现为视图跳位（虚拟化网格的固有取舍）。
- 网格列数按**推算宽度**计算：GPUI 未暴露子元素实测宽度，侧边栏 180ms 折叠动画期间可能出现最多一列的瞬时误差。
- 复制符号链接 / 目录联接时**拒绝并如实报错、不跟随**（跟随可能复抄整棵树、遇环时无限递归）——刻意行为，非缺陷。
- 全局唤醒热键走系统 `RegisterHotKey`：**`Win+组合` 一律注册不了**（`Win+字母` 都被
  shell 占着），因此默认用 `Ctrl+Alt+E`；能被别的程序抢占的组合会在设置页当场提示。
- 常驻的只有热键宿主，主窗口关闭即退出，热键响应时间取决于主程序冷启动耗时。
- 文件夹接管是**用户级注册表覆盖**：程序被删除或移动后双击文件夹会打不开，只能靠 `regedit` 或 `restore-explorer.bat` 修复——**卸载前务必先还原**。
- 任务栏「文件资源管理器」按钮拦不到：其固定项指向 shell 命名空间项而非文件夹路径，根本不经过「文件夹动词」；要接管只能替换任务栏固定项本身（个人化设置）。「此电脑」「回收站」走 CLSID 命名空间，同样不受影响；连它们一起接管只能改 `Winlogon\Shell`，超出本项目范围。
